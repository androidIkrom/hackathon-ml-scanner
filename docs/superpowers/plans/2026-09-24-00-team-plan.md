> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. **Goal:** Three people build the on-device scene assistant for blind users from `docs/build-guide.md` in parallel, in English and Korean, with a Korean-style accessible UI, without ever editing each other's files.

## Global Constraints

Every task in every plan implicitly includes these.

- Versions exactly as in Appendix A (`build.gradle`, `app/build.gradle`). Do not upgrade anything during the event.
- Java/Kotlin target is **17**, not the guide's 1.8: JDK 21 deprecates source/target 8 and prints warnings on every build. Nothing else changes.
- Portrait only (manifest). The heading and field-of-view maths assume an upright phone.
- No network at runtime, no cloud, no account. The one exception is the walk-mode route request, which falls back to the offline beacon when there is no network or key. Models are downloaded by Gradle into `app/src/main/assets/` and never committed.
- Every tuned number from `docs/build-guide.md` §4–§10 is used exactly and has a unit test that fails if it changes.
- The app never says "safe".
- **Text:** no user-visible text hard-coded in Kotlin UI code. Screen text lives in the owner's `res-X/values/strings.xml` **and** `res-X/values-ko/strings.xml`. Spoken sentences are built by pure `core` functions that take a `Lang` parameter.
- **Design tokens:** colours only through `?attr/ng…` theme attributes, text only through `@style/TextAppearance.Nungil.*`, buttons through `@style/Widget.Nungil.Button*`, cards through `@style/Widget.Nungil.Card*`, spacing through `@dimen/ng_*`. No raw colours in A's or Y's layouts.
- **Accessibility:** every screen has one heading (`ViewCompat.setAccessibilityHeading`), content descriptions on every icon-only control, touch targets at least 64 dp, and its main action as a full-width button at the bottom.
- **Threads** (guide §6): main thread for UI, `TextToSpeech`, `SpeechRecognizer`, navigation; one single-thread executor for camera analysis; one single-thread "extras" executor per screen for faces, embeddings, OCR and codes, each guarded by an `AtomicBoolean` busy flag that drops frames; database writes on `AppScope`; executor shutdown waits at most 2 s.
- **Logging:** tag `Nungil`, level `Log.i` (vendor builds hide `Log.d`).
- **Commits:** imperative subject describing the user-visible effect. Never add `Co-Authored-By` or any AI co-author line.

## Review Focus

Five inputs the spec implies but that tests rarely reach. Each line names the task whose tests pin it.

1. **Korean voice data missing on the phone** (Korean TTS voice or offline Korean speech recognition not installed): the app must say so once in English, keep working in English and show a visible hint to install it, never go silent. Pinned by I3 (`VoicePick` tests) and I9 (recognizer error mapping tests).
2. **Phone without a rotation-vector sensor** (`VisionFrame.headingDeg == null`): a full scan cannot measure coverage; it must say the "No compass" sentence from §5 and fall back to live behaviour instead of never finishing. Pinned by A10 (`ScanSession` null-heading tests).
3. **Dark room** (frame too dark for colours): objects are still named, never coloured, and no colour word appears in either language. Pinned by A7 (colour) and A9 (summary) tests.
4. **Unusual saved names** (Hangul names, names that are also command words such as "Me" or "나", 1-character names, names with digits): search, speech particles and the parser must all keep them intact. Pinned by Y1 (`SearchResolver`), I8 (`VoiceCommandParser` name tests) and the `JosaTest` in Task 0.
5. **Permission denied** (camera or microphone refused, or "don't ask again"): the screen says what it needs in the current language, shows a button to open app settings, and never crashes or loops. Pinned by each camera screen's task (A11, Y2, Y5, Y6, Y7) and I9; checked on the phone in QA item 1.

## 3. Contracts at a glance

The full code is in Appendix A. The rules each implementer must know:

- `Box` is normalised 0..1 in the **upright** image as the user sees it; the front camera's boxes are **not** mirrored (only `OverlayView` mirrors).
- `Detection.label` is the COCO English label exactly as the model emits it (`"cell phone"`, `"dining table"`). Display names come from `LabelNames.name(label, lang)`.
- `VisionFrame` arrives on the analysis thread. `bitmap` is present only with `keepBitmap = true`; never recycle it.
- `VisionFrame.headingDeg` is the compass heading of the **back** camera's view; A's `BoxGeometry.objectAngle` adds 180° for the front camera. `null` means no rotation sensor.
- `Speaker`, `Haptics`, `Beeper` are safe from any thread. `AppNavigator` is main-thread only.
- Screens implement `VoiceHandler` and return `true` only for commands they handle. `Repeat` is always handled by I (the speaker remembers the last sentence); screens never handle it.
- Screens that need free text (a name, a query) call `services().askForWords(viewLifecycleOwner) { text -> … }` and never create a `SpeechRecognizer`.
- `Dest` covers every screen. From anywhere: `services().navigator.open(Dest.Search("bag"))`. Inside your own flow you may also use `findNavController().navigate(R.id.<your destination>, <Args>(…).toBundle())`.
- Nav argument `saved.tab` is `SavedTab.ordinal` or `-1`. `search_camera.targetType` is `"LABEL"`, `"PERSON"` or `"ITEM"`.
- `data/` is version 1 with all six tables. Embedding vectors are `FloatArray` stored as little-endian bytes (Y's `VectorBytes`). Writes run on `AppScope`.
- `SettingsStore` is the only place scan settings live. A reads it when `CameraSession.start()` runs; I's Settings screen writes it.

**Who handles which voice command** (anything a screen does not handle falls back to I):

Rules for A and Y screens:

1. 20 dp side gutters (`@dimen/ng_gutter`), 12 dp between items (`ng_gap`), 24 dp between sections (`ng_gap_large`).
2. One headline per screen; say what the screen does in the user's words ("무엇을 찾을까요?" not "Search").

## 5. Language rules (English + Korean)

- `AppServices.lang` is the language for **everything**: UI (AppCompat per-app locales), speech output and speech recognition (`Lang.speechTag`: `en-US` / `ko-KR`).
- Screen text: each owner writes **both** `res-X/values/strings.xml` and `res-X/values-ko/strings.xml` in the same commit. A missing Korean string is a bug.
- Spoken text: built in pure `core` code with a `Lang` parameter and tested in both languages.
- Object names: `LabelNames.name(label, lang)`. Counts in Korean: `KoNumbers.count(n, LabelNames.counterKo(label))` ("의자 세 개", "사람 두 명", "노트북 한 대", "책 네 권", "개 두 마리"). Particles: `Josa.iGa / eulReul / eunNeun / waGwa`. English counts use digits ("3 chairs"); Korean uses native numbers up to 20.

### `tools/check-ownership.sh`

```bash
#!/usr/bin/env bash
# Usage: tools/check-ownership.sh <A|I|Y|C> <file>...
# Fails when a file belongs to somebody else according to OWNERS (longest prefix wins).
set -euo pipefail

who="$1"
shift
root="$(git rev-parse --show-toplevel)"
owners="$root/OWNERS"
status=0

for file in "$@"; do
    # Tests belong to the owner of the package they test.
    path="${file/\/src\/test\/java\//\/src\/main\/java\/}"
    path="${path/\/src\/androidTest\/java\//\/src\/main\/java\/}"
    best=""
    best_owner=""
    while read -r prefix owner _; do
        [[ -z "$prefix" || "$prefix" == \#* ]] && continue
        if [[ "$path" == "$prefix"* && ${#prefix} -gt ${#best} ]]; then
            best="$prefix"
            best_owner="$owner"
        fi
    done < "$owners"
    if [[ -z "$best_owner" ]]; then
        echo "UNOWNED   $file  (ask A to add its folder to OWNERS)"
        status=1
    elif [[ "$best_owner" != "$who" ]]; then
        echo "NOT YOURS $file  (owner: $best_owner, you are: $who)"
        status=1
    fi
done
exit $status
```

### `app/src/main/java/com/nungil/core/lang/Josa.kt`

```kotlin
package com.nungil.core.lang

/**
 * Korean particles that depend on whether the previous word ends in a consonant (batchim).
 * Hangul is exact; digits use their Sino-Korean reading; Latin letters use a small heuristic
 * (ends in l, m or n means batchim), which is right for most names.
 */
object Josa {
    private const val HANGUL_FIRST = 0xAC00
    private const val HANGUL_LAST = 0xD7A3
    private const val DIGITS_WITH_BATCHIM = "0136780"

    fun hasBatchim(word: String): Boolean {
        val c = word.trimEnd().lastOrNull { it.isLetterOrDigit() } ?: return false
        return when {
            c.code in HANGUL_FIRST..HANGUL_LAST -> (c.code - HANGUL_FIRST) % 28 != 0
            c.isDigit() -> c in DIGITS_WITH_BATCHIM
            else -> c.lowercaseChar() in "lmn"
        }
    }

    /** 이/가 (subject). */
    fun iGa(word: String): String = word + if (hasBatchim(word)) "이" else "가"

    /** 은/는 (topic). */
    fun eunNeun(word: String): String = word + if (hasBatchim(word)) "은" else "는"

    /** 을/를 (object). */
    fun eulReul(word: String): String = word + if (hasBatchim(word)) "을" else "를"

    /** 과/와 (and). */
    fun waGwa(word: String): String = word + if (hasBatchim(word)) "과" else "와"
}
```

```kotlin
/** Remembers the last scan settings in SharedPreferences "scan_settings". */
class SettingsStore(context: Context) {
    private val prefs = context.applicationContext.getSharedPreferences("scan_settings", Context.MODE_PRIVATE)

    fun load(): ScanSettings {
        val d = ScanSettings()
        return ScanSettings(
            facing = enumOr(prefs.getString(KEY_FACING, null), d.facing),
            compute = enumOr(prefs.getString(KEY_COMPUTE, null), d.compute),
            model = enumOr(prefs.getString(KEY_MODEL, null), d.model),
            minScore = prefs.getFloat(KEY_MIN_SCORE, d.minScore),
            speechOn = prefs.getBoolean(KEY_SPEECH, d.speechOn),
            colorsOn = prefs.getBoolean(KEY_COLORS, d.colorsOn),
        ).normalized()
    }

    fun save(settings: ScanSettings) {
        val s = settings.normalized()
        prefs.edit()
            .putString(KEY_FACING, s.facing.name)
            .putString(KEY_COMPUTE, s.compute.name)
            .putString(KEY_MODEL, s.model.name)
            .putFloat(KEY_MIN_SCORE, s.minScore)
            .putBoolean(KEY_SPEECH, s.speechOn)
            .putBoolean(KEY_COLORS, s.colorsOn)
            .apply()
    }

    private inline fun <reified E : Enum<E>> enumOr(name: String?, fallback: E): E =
        enumValues<E>().firstOrNull { it.name == name } ?: fallback

    private companion object {
        const val KEY_FACING = "facing"
        const val KEY_COMPUTE = "compute"
        const val KEY_MODEL = "model"
        const val KEY_MIN_SCORE = "min_score"
        const val KEY_SPEECH = "speech_on"
        const val KEY_COLORS = "colors_on"
    }
}
```

```kotlin
import androidx.camera.view.PreviewView

/**
 * BOOTSTRAP STUB (owner A). The signature is frozen; A replaces the body in task A9.
 *
 * Binds CameraX preview + analysis to [fragment]'s view lifecycle, runs the object detector chosen in
 * SettingsStore and delivers one [VisionFrame] per analysed frame to [onFrame] on the analysis thread.
 * Frames that arrive while [onFrame] is still running are dropped. [onError] runs on the main thread.
 */
class CameraSession(
    private val fragment: Fragment,
    private val previewView: PreviewView,
    private val options: Options,
    private val onFrame: (VisionFrame) -> Unit,
    private val onError: (Throwable) -> Unit,
) {
    data class Options(
        val facing: Facing = Facing.BACK,
        /** Run the object detector. false = frames only (face enrolment). */
        val detect: Boolean = true,
        /** Attach the upright bitmap to every frame (faces, items, colours). */
        val keepBitmap: Boolean = false,
        /** Fixed detector score floor; null = per-label DetectionFilter with the saved settings. */
        val minScore: Float? = null,
    )

    var facing: Facing = options.facing
        private set

    /** Horizontal field of view of the upright image; 65° until the camera reports its own. */
    val hfovDeg: Float
        get() = DEFAULT_HFOV_DEG

    /** Call from onViewCreated after the camera permission is granted. */
    fun start() = Unit

    fun switchCamera() {
        facing = if (facing == Facing.BACK) Facing.FRONT else Facing.BACK
    }

    /** Call from onDestroyView. Waits at most 2 s for the analysis thread. */
    fun stop() = Unit

    companion object {
        const val DEFAULT_HFOV_DEG = 65f
    }
}
```

### `app/src/main/java/com/nungil/shell/BootstrapSpeaker.kt`

```kotlin
package com.nungil.shell

import android.content.Context
import android.os.Handler
import android.os.Looper
import android.speech.tts.TextToSpeech
import com.nungil.contract.Lang
import com.nungil.contract.app.Speaker
import java.util.Locale

/** BOOTSTRAP (owner I). Minimal TTS so A and Y hear their phrases before I's real queue (task I3) lands. */
internal class BootstrapSpeaker(
    context: Context,
    private val lang: () -> Lang,
    private val onCaption: (String) -> Unit,
) : Speaker, TextToSpeech.OnInitListener {

    private val main = Handler(Looper.getMainLooper())
    private val tts = TextToSpeech(context.applicationContext, this)

    @Volatile
    private var ready = false

    override fun onInit(status: Int) {
        ready = status == TextToSpeech.SUCCESS
        if (ready) tts.language = Locale.forLanguageTag(lang().speechTag)
    }

    override fun say(text: String) = speak(text, TextToSpeech.QUEUE_ADD)

    override fun sayNow(text: String) = speak(text, TextToSpeech.QUEUE_FLUSH)

    override fun sayFinal(text: String, onDone: () -> Unit) {
        speak(text, TextToSpeech.QUEUE_FLUSH)
        main.post(onDone)
    }

    override fun stop() {
        tts.stop()
    }

    fun shutdown() = tts.shutdown()

    private fun speak(text: String, mode: Int) {
        main.post { onCaption(text) }
        if (ready) tts.speak(text, mode, null, text.hashCode().toString())
    }
}
```
